# QA Atlas 0.5.0 — обновление с автопрогонами

## Обновление вашей работающей установки (Windows PowerShell)

1. Сохраните резервную копию данных из старой папки:

```powershell
docker compose exec backend node backend/src/backup.mjs
```

2. Распакуйте новый проект. Скопируйте **свой действующий `.env`** из старой папки в новую. Имя модели, ключ, URL, `AI_PROVIDER`, `ML_TOKEN` и `PUBLIC_ORIGIN` менять не требуется. В архив секретный `.env` не включён.
3. Откройте терминал в новой папке рядом с `compose.yaml`. Docker Desktop должен работать в режиме Linux containers. Выполните по очереди; при ошибке остановитесь:

```powershell
docker compose --profile build-worker build worker-image
docker compose up -d --build --wait backend ml-service runner
docker compose exec backend node scripts/check_runner.mjs
```

Первая сборка загружает большой образ Playwright с браузерами и может занять несколько минут. Последняя команда проверяет оба языка **в настоящих одноразовых контейнерах**, без ИИ и расходов на API. Ожидается:

```text
pytest: OK, 1 test passed, coverage 100%
playwright: OK, 1 test passed, coverage 100%
```

Те же шаги с остановкой при ошибке: `powershell -ExecutionPolicy Bypass -File scripts/update.ps1`.

4. Откройте http://localhost:8080 (либо адрес из вашего PUBLIC_ORIGIN) и обновите страницу Ctrl+F5. На странице входа выберите «Нет аккаунта? Зарегистрироваться», чтобы создать новый аккаунт прямо на сайте. Старые аккаунты и проекты сохраняются в прежнем томе: имя Compose-проекта остаётся `qa-atlas`. Не используйте `docker compose down -v` — эта команда удаляет данные.

## Как работать на сайте

1. В «Обзоре проекта» загрузите требования и отдельно исходники `.py` / `.js`. Дождитесь завершения импорта. Ниже отображается содержимое исходников.
2. Выберите требования, включите генерацию кода. ИИ возвращает Gherkin, pytest и Playwright, когда переданный контекст позволяет их создать. Если нет исходников нужного языка, его артефакт остаётся пустым с вопросом от модели. Настройки вашего DeepSeek используются из `.env` без замены.
3. Проверьте код и допущения. Если старые тесты содержат вместо переводов строк буквальные `\n`, исполнитель исправит однозначный вариант; если синтаксис восстановить нельзя, тест не запустится, а появится понятная ошибка. Перед запуском новых партий генератор получает названия/сценарии уже существующих тестов и последние измеренные непокрытые строки (если такой прогон есть); это **не гарантирует** роста покрытия, но помогает избегать повторов.
4. Во вкладке «Автопрогоны» выберите pytest или Playwright, отметьте нужные тесты и нажмите «Запустить». Можно запускать и один тест из его карточки.
5. Дождитесь отчёта. «Завершён» означает завершение задания; внутри отчёта отдельно указан успех, падение или ошибка исполнения тестов. Доступны логи, отмена и JSON-отчёт. Ошибки импорта и отсутствие тестов не считаются успешным прогоном.
6. Во вкладке «Покрытие кода» выберите прогон и файл. Зелёные строки со знаком `+` выполнены, красные со знаком `−` не выполнены. Нейтральные строки не учитываются либо данных для файла нет. Показывается сохранённый снимок; после изменения кода/тестов появляется предупреждение об устаревании.
7. В карточке теста скачайте `.feature`, `.py`, `.js`. Общий ZIP содержит артефакты, исходники, проект и последние 50 автопрогонов. Ручные прогоны остаются отдельной функцией.

Главная панель показывает количество тест-кейсов, покрытие строк и долю успешных проверок последнего доступного автопрогона. Пропущенные проверки не включаются в процент успеха. Покрытие требований — отдельная метрика, не подмена покрытия строк.

## Готовое демо без расходов на ИИ

В контейнер backend включён `examples/autorun/project.json`. Укажите email своего существующего аккаунта:

```powershell
docker compose exec backend node backend/src/import-project.mjs "ВАШ_EMAIL" examples/autorun/project.json
```

Это создаёт отдельный демонстрационный проект. Обновите страницу и выберите его. В «Автопрогонах» запустите только «Положительное число»: часть строк будет красной. Затем выберите оба теста — покрытие станет 100%. Повторите для Playwright. Чтобы показать падение, измените ожидаемый результат одного pytest-теста на `wrong`, сохраните и запустите его снова.

## Область поддержки и ограничения

- Исполняются Python-модули со standard library/pytest и JavaScript-модули с Node/Playwright. Все исходники одного языка отправляются вместе. Поддерживаются простые имена файлов латиницей, без директорий. В Python импортируйте `from target import ...`, в JS — `../src/target.js`.
- JUnit, TypeScript, установка пользовательских зависимостей, полноценный запуск стороннего веб-приложения и тестирование внешних URL не реализованы. Для них сохраняется экспорт кода.
- JavaScript-покрытие собирается c8 в Node. Покрытие JS, исполненного внутри браузерной страницы, отдельно не собирается. Не выдавайте его за браузерное E2E-покрытие.
- Каждому прогону выделяется отдельный контейнер: без сети, без томов и секретов приложения, с read-only rootfs, непривилегированным пользователем, ограничениями памяти, CPU, процессов, размеров файлов и временем до 75 секунд. Покрытие — процент исполняемых строк, не ветвей.
- Сервис `runner` управляет Docker через сокет и потому является привилегированной доверенной частью системы. Его порт наружу не опубликован, запросы требуют внутренний токен. Контейнеры тестов сокета не получают. Для публичного сервиса с произвольными недоверенными пользователями нужен отдельный runner-хост/VM и дополнительная защита: обычные Docker-контейнеры не равны виртуальным машинам.
- Если pytest не смог собрать тесты, процент покрытия не показывается — это ошибка подготовки, а не результат измерения.
- Отчёты формируются из вывода пользовательского кода и предназначены для командной работы, а не как защищённое доказательство против намеренной подделки.
- Сборка и локальные тесты проверены; полный Docker-путь и ваша рабочая модель в среде подготовки не запускались. Команда `check_runner.mjs` — обязательная финальная проверка на вашем Docker Desktop/сервере. Это кандидат для приёмки, а не подтверждение промышленной аттестации.

## Если запуск не работает

```powershell
docker compose ps
docker compose logs --tail=100 runner backend ml-service
docker compose exec backend node scripts/check_runner.mjs
```

- `Соберите образ qa-atlas-worker:1`: выполните первую команду сборки из начала инструкции.
- `Cannot connect to Docker daemon`: запустите Docker Desktop, проверьте режим Linux containers и доступ к `/var/run/docker.sock`.
- `ModuleNotFoundError`: проверьте имя исходного файла, импорт и доступные зависимости. Это ошибка загруженного теста, а не успешный прогон.
- Нет кода для фреймворка: загрузите исходники нужного языка, сгенерируйте/вставьте соответствующий тест.
- Ошибка ИИ: `docker compose exec ml-service python -m app.check_ai`. Этот запрос использует вашу модель и может тарифицироваться.

## Разработчикам

- `frontend/src/AutoRuns.tsx` — загрузка, просмотр кода, запуск, история, покрытие, экспорт отдельных артефактов.
- `backend/src/jobs.mjs`, `autorun.mjs`, `index.mjs` — авторизация, очередь, снимки, маршруты `/auto-runs`.
- `runner/service.py` — доверенный контроллер Docker; `worker.py` — выполнение и извлечение отчётов.
- `ml-service/app/generator.py`, `models.py` — контракт с моделью, включая оба артефакта.
- `docs/VERIFICATION.md` — выполненные проверки и оставшаяся проверка Docker.
