# Соответствие кейсу № 9

Источник: предоставленная презентация «Презентация — мероприятие ТПУ», слайды 33–35; общие требования — слайды 5–6. Оценка относится к версии 0.6.0.

| Официальный критерий | Реализация и проверка | Ограничение |
|---|---|---|
| 1. Gherkin Given/When/Then | Нормализация, проверка шагов, строгая JSON-схема, дедупликация и ограниченная повторная генерация; Python-тесты | Проверка структурная, не полный Cucumber parser; реальная модель не вызвана |
| 2. Генерация Python + pytest | AST-проверка Python, нормализация переносов; pytest выполнялся в локальном runner | Качество ответов живого провайдера не проверено |
| 3. Подсветка покрытого/непокрытого кода | Сохранённые снимки и построчный CodeView, тест интерфейса jsdom | Визуальная браузерная приёмка не выполнена |
| 4. coverage.py / Istanbul | Реальный coverage.py и c8, проходящие/падающие проверки, неисполненные файлы, отсутствие покрытия при ошибках | Docker не проверен; JS покрытие только Node |
| 5. Экспорт .feature, .py, .js | Отдельные файлы и ZIP проекта; HTTP-интеграционные проверки | Экспортируемый код требует собственного окружения приложения |
| 6. QA-дашборд | Количество тестов, измеренное покрытие, доля успешных, история и детализация; сравнение одинаковых снимков | Нет измерений браузерного кода и нагрузочной приёмки |
| 7. Docker Compose | Сервисы и Dockerfiles сохранены, добавлен Node в ML для JS-проверки; YAML разобран | Требуется .env и предварительная сборка worker-image. «Одна команда» с чистого окружения не подтверждена |

## Рабочий процесс (слайд 34)

Загрузка требований PDF/DOCX/MD и исходников PY/JS/Java, генерация, экспорт и отображение измерений реализованы. Java не исполняется. Тесты документов проверяют извлечение поддерживаемых форматов, но не OCR и не норматив времени для файлов >50 страниц.

## Общие требования (слайды 5–6)

React SPA и Node REST API соответствуют допустимому стеку; тяжёлые операции вынесены в асинхронные задания. **PostgreSQL, отдельная Celery/RabbitMQ/Redis-очередь и векторное хранилище не реализованы.** Используется SQLite и один worker backend. Поэтому полного соответствия общему стеку и всех критериев приёмки заявлять нельзя.
