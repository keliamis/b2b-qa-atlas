## Новое: сравнение прогонов

Откройте «Автопрогоны». В истории выберите текущий прогон, а в блоке сравнения — базовый прогон того же фреймворка.

- «Начали падать»: тот же тест-кейс и неизменённый код проверки перешёл PASS → FAIL.
- «Снова проходят»: FAIL → PASS при неизменённой проверке.
- «Проверка изменена»: изменены код, сценарий или состав отдельных проверок. Такой переход не выдаётся за исправление продукта.
- «Добавлены / не вошли»: различается выборка тестов в снимках, что не означает создание/удаление теста из проекта.
- «Недостаточно данных»: нет индивидуальных результатов, есть пропуски либо ошибка запуска.

Показатель агрегируется по тест-кейсу: если в нём несколько pytest-проверок и хотя бы одна упала, результат FAIL. Изменение исходников явно отмечается. Разница процентов покрытия показывается только для одинакового содержимого исходников. Названия файлов и текст учитываются, технические ID загрузок и порядок файлов — нет.

Сравнение можно отфильтровать и скачать в Markdown вместе с идентификаторами обоих прогонов. Это удобно для ревью исправления и передачи результата разработчику.

## Новое: кандидаты на нестабильность

В том же разделе анализируются до 50 последних доступных автопрогонов. Кандидат появляется только при минимум трёх сопоставимых выполнениях и минимум двух переключениях результата: например PASS → FAIL → PASS.

Сопоставляются:

- ID тест-кейса и фреймворк;
- одинаковые тексты и имена исходников;
- одинаковый код теста и Gherkin;
- одинаковый набор имён индивидуальных проверок.

Пропуски, отсутствие индивидуальных результатов и ошибки исполнения не используются как доказательство нестабильности. Простой переход FAIL → PASS после исправления не помечается как flaky. Для кандидата доступны даты, результаты и кнопки открытия исходных прогонов; доказательства экспортируются в JSON.

Это сигнал для расследования, не автоматический диагноз. Порядок других тестов, системное время, версия worker-образа и окружение могут влиять на результат и не полностью отражены в снимке. Поэтому функция ничего не удаляет, не отключает и не запускает автоматически. Недостаток истории не трактуется как подтверждённая стабильность.

## Что очищено в коде

- Повторяющаяся выгрузка файлов из AutoRuns и Insights перенесена в `download.ts`; ссылки освобождаются единообразно.
- Выбор артефакта, актуальность снимка и сравнение исходников собраны в `runAnalysis.ts` с типами данных.
- Аналитика отделена от UI в `RunIntelligence.tsx`; не раздувает основной App дополнительными вычислениями.
- Убраны неиспользуемый импорт RefreshCw и создание неиспользуемой таблицы старых хеш-векторов при новой установке. Уже существующая legacy-таблица и данные не удаляются.
- При смене проекта история и выбор тестов в AutoRuns сбрасываются, чтобы не показывать состояние предыдущего проекта.
- Повторная загрузка одинаковых исходников с новыми ID больше не помечает отчёт устаревшим только из-за метаданных.

Новые библиотеки и миграции не добавлены. Большой App.tsx и несколько исторических слоёв CSS оставлены: их полное разделение перед сдачей увеличило бы объём и риск изменений. Очередь по-прежнему рассчитана на один backend-инстанс.
