# QA Atlas 0.7.1 — исправления

## Выполнено
- BUG-001: количество хранится строкой, допускает очистку и ввод с клавиатуры; проверка целого 1–100 перед отправкой.
- BUG-002/003: ровно N уникальных записей либо HTTP 422 с доступным количеством. Позитивные числовые данные распределены между классами порогов. Decimal 10.6.0 используется для арифметики шага и границ. Денежное форматирование в таблице и CSV. CSV/JSON используют один набор записей. Отрицательные числовые значения CSV не превращаются в строки с апострофом.
- BUG-004/005: группы числовых рекомендаций, раскрытие одной группы, фильтр приоритета; отдельно связь, возможное соответствие и результат выполнения. Возможное соответствие определяется эвристикой общих слов и требует ручного подтверждения. Отсутствие связи не объявляется отсутствием тестирования.
- BUG-006: новый режим scenario существующего ML-сервиса выделяет атомарные правила и конкретные Given/When/Then. Сервер проверяет структуру и отвергает шаблоны/Markdown в шагах. Сохраняются черновики, неоднозначности возвращаются вопросами. Никакого копирования полного документа в Then.
- BUG-007: совместимое поле duplicateOf в тесте и серверной схеме; метка, основной тест, отмена, счётчики. Сохранение через существующее хранилище с ревизией. Массовый выбор автотестов пропускает дубликаты; индивидуальный выбор остаётся доступным. Удаление основного теста снимает ссылку у оставшихся.
- BUG-008: разные числовые входы и разные явно указанные исключения не объединяются. Сходство текста остаётся кандидатом на ручное ревью, автоматического удаления нет.
- BUG-009: блокировка повторных действий, контроль устаревших ответов при смене проекта/прогона, проверка ревизии после AI-запроса, ограничение контекста вместо молчаливого усечения. Неудачная генерация не стирает сохранённые данные.
- Detective и Bug Report: сохранены реальные traceback, ожидаемое из снимка Gherkin, фактическое из результата; гипотезы помечены. Отчёты редактируются, сохраняются и экспортируются.

## Проверки
TypeScript и сборка выполнены. 10 целевых проверок генератора данных, рекомендаций, дубликатов, API и компонентов прошли. Python-модули проверены на синтаксис. Полный набор повторно не запускался по просьбе пользователя. Docker не запускался по просьбе пользователя. Живой LLM и браузерный E2E в этом обновлении не проверялись; API-тесты используют контролируемый ответ провайдера.

## Практические ограничения
Корректность извлечённых LLM правил и ожидаемых результатов требует ревью. Синтаксическая проверка не доказывает бизнес-корректность. Свободный текст сопоставляется эвристически, а не доказательно. При недостатке уникальных вариантов генерация возвращает явную ошибку вместо повторов. Произвольные зависимости полей и регулярные выражения не вычисляются генератором. JSON хранит числа без обязательных конечных нулей; таблица и CSV учитывают precision. Поле duplicateOf независимо от статуса ревью draft/review/approved, что сохраняет совместимость старых проектов.
