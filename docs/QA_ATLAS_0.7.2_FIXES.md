# QA Atlas 0.7.2: фиксация изменений и ограничения проверки

## Исправлено

- Импорт требований: исходные заголовки `REQ-xxx` теперь выделяются в отдельные бизнес-требования, а не смешиваются в текстовые фрагменты по 6000 символов. Для файлов без явных идентификаторов создаются страницы/фрагменты как отдельные черновики.
- Номера страниц PDF сохраняются в тексте импорта. Поддержаны несколько правил на странице и правила на разных страницах.
- Поиск требований в форме генерации и ясное указание лимита: *20 выбранных за один AI-запрос*, а не только 20 требований документа. Лимит 15 генерируемых кейсов за один запрос оставлен намеренно.
- Максимальный размер извлечённого текста увеличен с 120000 до 500000 символов без молчаливого усечения. Лимит проекта при сохранении увеличен с 2 до 10 МБ.
- Compose при первой установке создаёт внутренний токен, автоматически собирает тестовый worker image. Локальный запуск не требует предварительного Python-скрипта.
- README обновлён, добавлены примеры API и инструкция проверки документа на 51 страницу.
- Добавлены регрессионные тесты и контрольный 51-страничный PDF.

## Проверка

- Путь импорта PDF проверен на реальном файле `examples/long-document/requirements_51_pages.pdf`: извлечены 51 исходный идентификатор, включая `REQ-001`, `REQ-025` и `REQ-051`.
- Включены автоматические JS-тесты выделения требований и Python-тест на извлечение текста PDF.
- Docker Compose требуется испытать на машине с Docker Engine; в среде подготовки Docker отсутствует. Работа внешнего LLM-провайдера также требует отдельной проверки.

## Что не следует считать доказанным

- Тест одного 51-страничного PDF **не гарантирует** отсутствие HTTP 504 для любых файлов, в том числе PDF со сканами/изображениями: OCR не реализован.
- Высокая нагрузка, большие DOCX, внешние модели и веб-интерфейс в реальном браузере требуют приёмки в целевом окружении.
- Отдельные текстовые ограничения на одно LLM-задание сохраняются, чтобы не перегружать модель.
