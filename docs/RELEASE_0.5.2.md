# QA Atlas 0.5.2 — удаление данных и автопрогоны

Основание: обратная связь по интерфейсу версии 0.5.1.

## Что добавлено

- **Тест-кейсы → Удалить все тесты.** Удаляет все сценарии текущего проекта, в том числе скрытые фильтром или на других страницах таблицы (не только текущие 50). Система спрашивает подтверждение. Требования и исходники остаются.
- **Тест-кейсы → Удалить выбранные.** Массовое удаление отмеченных чекбоксами сценариев с подтверждением.
- **Настройки → Удалить проект.** Потребуется ввести его название в точности. На сервере только владелец проекта может его удалить; доступ со стороны участников не помогает обойти эту проверку. Удаляются серверные связанные записи (участники, приглашения, обсуждения, сохранённые представления, ручные прогоны, дефекты, AI-задачи, отчёты и сам проект), но НЕ учётные записи пользователей и НЕ другие проекты.
- Во время генерации либо выполнения автоматического прогона проект удалить нельзя: сначала завершите или отмените активное задание. Отмена не удаляет историю проекта.
- После удаления последнего проекта показывается отдельный экран создания нового проекта — удалённый пример не восстанавливается автоматически.
- При удалении отдельных тест-кейсов очищаются обсуждения удалённых сценариев. Старые отчёты автопрогонов, снимки ручных прогонов и дефекты остаются историческими записями. Процент покрытия автопрогонов после изменения тестов отмечается как устаревший до нового запуска.
- Из справки и настроек удалена неверная строка «Автоматическое исполнение тестов пока не подключено». В настройках отображается фактическое состояние сервиса по `/api/config` (на момент загрузки страницы).
- В панели профиля уточнено, что регистрация самостоятельная.

## Есть ли автоматическое исполнение?

**Да.** `runner` управляет изолированными одноразовыми Docker-контейнерами с `pytest/coverage.py` и `Playwright/c8` для поддерживаемых Python/JavaScript-модулей. Вторая часть не означает поддержку настоящего браузерного E2E: Playwright здесь исполняется как Node-тест. Ограничения — 50 кейсов на один запуск, 75 секунд и отсутствие произвольной установки зависимостей.

Чтобы проверить доступность исполнителя на сервере:

```bash
docker compose --profile build-worker build worker-image
docker compose up -d --build --wait backend ml-service runner
docker compose exec backend node scripts/check_runner.mjs
```

После этого откройте **Автопрогоны**, выберите `pytest` или `Playwright`, отметьте тесты и нажмите **Запустить**. Если `runner` не готов, проверьте его состояние и журнал:

```bash
docker compose ps
docker compose logs --tail=100 runner
```

## Безопасность обновления

Сохраните `.env` и сделайте резервную копию базы перед обновлением, а также экспортируйте важные проекты. **Не выполняйте `docker compose down -v`**, поскольку том `atlas_data` содержит данные. Удаление проекта/тестов — необратимо без резервной копии.

## Проверки этой сборки

- Пройден разбор синтаксиса обновлённых `App.tsx`, `CaseLibrary.tsx` и `workspace.ts` средствами TypeScript; полученный JavaScript проходит `node --check`.
- `node --check` пройден для изменённых серверных модулей и тестовых файлов.
- SQL-схема всех 4 миграций разворачивается в SQLite; операции удаления связанных строк проверены в изолированной тестовой базе, другой проект сохранён.
- Добавлены Node-интеграционные тесты удаления с правами владельца, запретом при активной задаче и очисткой связанных таблиц; добавлен jsdom-сценарий удаления всех кейсов и последнего локального проекта.
- Полный запуск Node-тестов, `npm run typecheck` и production-сборка **не выполнены в этой среде**, поскольку `npm ci` не смог скачать пакеты с registry.npmjs.org (`EAI_AGAIN`). Требуется запуск в вашей Docker/GitHub Actions среде.
- Полный Docker-smoke и реальный браузерный тест на сервере не выполнялись.
