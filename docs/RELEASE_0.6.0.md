# QA Atlas 0.6.0 — результат доработки

Основание: пользовательский промпт из `message (15).txt`, презентация ТПУ, слайды 5–6 и 33–35. Дата: 30 октября 2026.

Это обновлённый проект с проверенными исправлениями, а не аттестованная production-система. Полный объём промпта не закрыт; ограничения ниже являются частью результата.

## Исправленные ошибки

- Два одновременных запроса регистрации одного email теперь дают один успех и HTTP 409, а не необработанную ошибку уникальности SQLite после асинхронного хеширования.
- `null` в запросе входа возвращает ошибку валидации вместо HTTP 500.
- Форма регистрации не отправляет несовпадающие пароли, блокирует повторную отправку и переключение режима до завершения запроса, ограничивает время ожидания.
- JavaScript проверяется через `node --check` без исполнения; валидные строковые литералы с `\n` сохраняются. Невалидные артефакты не сохраняются как успешные автотесты.
- Повторное название Feature/Scenario больше не обходит сравнение дублей с одинаковым содержимым шагов.
- Пустой набор тестов, таймаут и ошибка подготовки не показывают частичное покрытие как достоверное измерение.
- Исправлены две устаревшие проверки исходного набора тестов: кнопка настроек находится вне `nav`, число аккаунтов в резервной копии учитывает самостоятельную регистрацию.
- В списке фоновых задач автопрогон больше не подписан как генерация.

## Новые возможности

- Восстановление пароля и подтверждение почты через SMTP с обязательным TLS. В БД хранятся только хеши случайных одноразовых токенов, TTL 30 минут. Сброс отзывает все сессии. Проверена защита от конкурентного повторного использования ссылки. Без SMTP кнопки запроса писем не отображаются.
- Архивирование и восстановление проекта владельцем, без удаления истории. Сервер блокирует запись и новые задания архивного проекта. Архивация запрещена при активных фоновых заданиях. Данные доступны для чтения и экспорта.
- Один повторный запрос к модели для отклонённых сценариев/артефактов; принятые результаты не перегенерируются. После неудачи возвращается диагностическая причина. Невалидный JSON всей выдачи отклоняется без повторного запроса.
- Результаты отдельных pytest/Playwright-проверок, длительности, сравнение покрытия с предыдущим измерением на тех же исходниках. Числовая цель покрытия в отчёте — локальный ориентир интерфейса, она не обещает автоматического достижения цели.
- Обновлённая регистрация: компактная форма, показ пароля, состояния ожидания и ошибок, focus-visible и reduced-motion, мобильные стили.

## Архитектурные изменения

Сохранены frontend (React/TypeScript), backend (Node/SQLite), ML (FastAPI) и Docker runner. Нет миграции данных на другую СУБД. Добавлена аддитивная миграция `0004_account_recovery.sql`, отдельный модуль `recovery.mjs`, компонент `AccountRecovery.tsx`. В ML-образ добавлен Node для синтаксической проверки JS. AI-провайдер, URL, модель и ключ остаются конфигурируемыми. Новый `archived` — необязательное поле существующего JSON проекта. Старые API остаются доступны.

CI дополнен проверкой синтаксиса JS и тестами runner. Сам workflow в GitHub Actions не запускался. `check:syntax` — проверка парсинга, не полноценный ESLint-анализ.

## Незавершённые пункты и ограничения

- PostgreSQL, Redis/RabbitMQ/Celery, векторная БД из общего стека презентации не внедрены. Сохранён однопроцессный SQLite-пилот с устойчивой очередью в БД. Прерванные при рестарте задания требуют повторного запуска.
- Роли остаются Owner / Tester / Viewer. Отдельные Admin / Member не добавлены. Обязательная верификация email, SSO/MFA не реализованы; подтверждение email добровольное и не является обязательным условием приглашения.
- Нет полной переработки всех экранов и подтверждения WCAG 2.2 AA. Настоящий браузер и визуальная проверка 320/375/768/1024/1440/1920 px не выполнены, скриншотов нет. Скачивание Chromium дважды завершилось повреждённым/пустым архивом; jsdom проверяет поведение, не вёрстку.
- Нет итеративного автоматического цикла «генерация → запуск → достижение заданного покрытия». Учитываются существующие сценарии и реальные пропущенные строки актуального снимка; отдельного AST-анализа всех функций/ветвей и семантической дедупликации нет. Синтаксическая корректность не гарантирует правильность теста.
- Runner ограничен загруженными Python/JS-модулями без установки произвольных зависимостей. Java можно загружать, но исполнять нельзя. Для Playwright измеряется JS в Node, не код браузерного приложения.
- Docker CLI/daemon отсутствуют: реальная изоляция, образы, healthchecks и сетевые ограничения контейнеров не проверены. Контроллер имеет Docker socket; пользовательский код разделяет контейнер с обработчиком отчётов, поэтому отчёт нельзя считать защищённым от намеренной подделки. Не использовать эту сборку как публичную песочницу для враждебного кода без дополнительной изоляции и доверенного сбора результатов.
- Нет теста реального AI-провайдера и отправки реального SMTP-письма. Проверки используют моки доставки и ответов модели. Доставка может не состояться; ошибка пишется в серверный журнал без секрета, а публичный ответ одинаков для зарегистрированных и неизвестных адресов.
- Не проверены большие документы 50+ страниц, OCR, нагрузка, горизонтальное масштабирование и полная цепочка в Docker. Удаление остаётся необратимым; для сохранения данных используйте архивирование и резервные копии.
- Не добавлены полноценная история версий каждого тест-кейса, flaky-анализ, интеграция с внешним Git CI и автоматическая доставка отчётов руководителю. Существующие связи требований, ручные прогоны, дефекты и аудит сохранены.

Все результаты выполненных проверок — в `VERIFICATION.md`, соответствие официальному кейсу — в `CASE9_AUDIT.md`, обновление — в `UPGRADE_0.6.0.md`.
