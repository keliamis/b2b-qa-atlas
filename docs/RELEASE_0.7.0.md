# QA Atlas 0.7.0 — AI Features

## Запуск в Windows PowerShell
Требуются Docker Desktop (Linux containers, запущен) и Python 3 с командой `py`.

```powershell
Expand-Archive -LiteralPath .\QA_Atlas_0.7.0_AI_Features.zip -DestinationPath .\QA_Atlas_0.7.0
Set-Location .\QA_Atlas_0.7.0\qa-atlas
py -3 scripts/init_env.py http://localhost:8080
notepad .env
# Сохраните OPENAI_API_KEY и OPENAI_MODEL; при необходимости OPENAI_BASE_URL и AI_PROVIDER.
docker compose --profile build-worker build worker-image
docker compose up -d --build
docker compose ps
Start-Process http://localhost:8080
```

В браузере зарегистрируйте учётную запись. Без ключа доступны отчёты, рекомендации и поиск повторов; AI Bug Detective и извлечение ограничений для данных требуют LLM. Не копируйте `.env` из чужой установки.

При обновлении существующей установки сохраните её `.env` и именованные тома. Выполните резервное копирование по `docs/OPERATIONS.md`, замените исходники, пересоберите worker и `docker compose up -d --build`. Не выполняйте `docker compose down -v`. Миграция `0005_ai_features.sql` применяется автоматически, добавляет таблицу и не изменяет старые проекты.

## Пять функций и точки входа

1. **AI Bug Detective**: «Автопрогоны» → результат → «Результаты отдельных проверок» → FAILED → «Анализировать ошибку с ИИ». Отправляются ограниченные и очищенные фрагменты traceback, assertion, сценария, кода теста и исходников из снимка. Причина и исправление явно показаны как гипотезы. При отсутствии traceback уверенность принудительно низкая. Ошибка провайдера не скрывает журнал.
2. **Bug Report Generator**: рядом с упавшей проверкой → «Создать баг-репорт». Отчёт сохраняется сразу; можно редактировать Markdown, просмотреть текст, скопировать, экспортировать и повторно открыть в «Сохранённых баг-репортах». Повторное создание открывает существующий отчёт, не затирая правки. AI-анализ, если уже существует, добавляется отдельно от фактов. Severity предварительная, редактируется в тексте. Баг-репорты также входят в экспорт проекта.
3. **Smart Coverage Advisor**: «Покрытие кода» → «Рекомендации по покрытию» → «Проверить пробелы». Отдельно показывает число требований со связанными тестами и покрытие строк последнего прогона. Ищет числовые условия, отсутствующие во входных шагах связанных сценариев, и непокрытые строки актуального снимка. «Создать тест-кейс» использует обычное сохранение проекта: только черновик с допущением для ревью. Повторите проверку после изменения тестов.
4. **Test Data Generator**: «Требования» → выбор позитивного, негативного, граничного или смешанного набора → количество 1–500 → генерация. LLM извлекает типы, обязательность, форматы, диапазоны и точность. Числовые окрестности вычисляются сервером детерминированно. Доступны предпросмотр ограничений/записей и CSV/JSON. CSV защищает текстовые ячейки от формульной интерпретации; JSON сохраняет типы. Набор не сохраняется в БД — скачайте его до перехода в другой раздел.
5. **Test Case Deduplicator**: «Тест-кейсы» → «Найти дубликаты». Нормализация шагов без названий, затем лёгкое сравнение токенов с небольшим словарём синонимов. Разные числовые значения исключаются. Можно открыть оба сценария, оставить оба или сохранить отметку дубликата. Тесты не удаляются; решение сбрасывается при изменении пары.

## Пример

Создайте проект и загрузите `examples/ai-features/requirements.md` и `pricing.py` через «Материалы проекта» (исходник намеренно содержит ошибку). До добавления теста советник предложит проверить ровно 5000.00. Создайте черновик, уточните сценарий:

```gherkin
Feature: Скидка
Scenario: Ровно 5000 рублей
Given корзина на сумму 5000.00 рублей
When рассчитывается итог заказа
Then итог равен 4500.00 рублей
```

Вставьте содержимое `examples/ai-features/test_boundary.py` в pytest-код тест-кейса (не загружайте этот файл как исходник приложения). Запустите его: ожидается FAILED, фактический итог 4750.00. Откройте анализ и отчёт. Скопируйте сценарий с другим названием, чтобы проверить обнаружение дубликатов. Сценарий на 4999.99 должен оставаться самостоятельным.

## Ограничения

- Старые прогоны не имеют индивидуального traceback, сценария и достоверной связи с тест-кейсом. Данные не выдумываются; для полноценного анализа нужен новый прогон.
- Анализ покрытия эвристический: число в тексте может быть примером, а не границей. Поддерживаются числа с десятичной точкой/запятой без разделителей тысяч; сложные условия требуют ручного ревью. Ни связь с требованием, ни наличие числа в шаге не доказывают полноту проверки.
- Сравнение сценариев не является универсальной моделью смысла: произвольные перефразирования могут быть пропущены. Возвращается до 200 пар за запрос; отличия кода показаны для ревью.
- Данные поддерживают number/integer/string/boolean и text/email/date. Произвольные регулярные выражения и межполевые бизнес-зависимости требуют проверки. Неизвестная точность числа — явно обозначенный шаг 0.01. Повторение базовых записей допустимо. Email всегда синтетический `example.invalid`.
- Очистка секретов работает по распространённым паттернам и настроенным серверным ключам; произвольные необозначенные секреты нельзя надёжно распознать. Не загружайте их в материалы проекта.
- LLM не исполняет код, не меняет исходники и не утверждает тесты. Тестовый код запускается только существующим runner по действию пользователя.
- Доступ новых серверных функций требует сессии. Viewer может читать рекомендации и отчёты, но не запускать AI и не сохранять изменения.
