# 0.7.2 — ошибки генерации и переход на требуемый стек

Исправления: числовые кандидаты извлекаются из входного столбца таблиц и формулировок входных ограничений, а не ожидаемых выходов/нумерации. Нормализуются JSON-ограждения, test_cases/cases, отсутствующие необязательные метаданные, экранированные переносы и русские Gherkin-ключи. При несоответствии основной схемы выполняется один повторный запрос исправления формата. Смысл отсутствующих шагов не выдумывается.

Автопрогоны теперь показывают отдельный список тестов без кода выбранного фреймворка. Отмена duplicateOf сама по себе не генерирует код; тесты с кодом доступны для индивидуального выбора, массовый выбор пропускает только отмеченные дубликаты.

Compose: PostgreSQL 16 + pgvector, Redis с AOF, автоматическая сборка worker-image. DATABASE_URL включает PostgreSQL-адаптер; SQLite оставлен для локальных проверок и переноса старых данных. Redis управляет пробуждением сохранённых заданий, PostgreSQL хранит статус и данные. Поддерживается один backend: не масштабировать replicas без отдельного распределённого блокирования.

pgvector хранит 128-мерные векторы требований, использует поиск ближайших фрагментов при подготовке атомарных сценариев. Это локальная лексическая hash-vector модель, НЕ обученная семантическая multilingual embedding-модель; качество поиска ограничено совпадениями лексики. Индексация выполняется при анализе требований.

## Данные при обновлении
Старый atlas_data не удаляется. PostgreSQL — новое хранилище, автоматического переноса нет. Сначала сохранить SQLite-резервную копию старой версии. Затем запустить postgres/redis, собрать backend и перенести данные в пустую PostgreSQL:

```powershell
docker compose up -d postgres redis
docker compose build backend ml-service
docker compose run --rm --no-deps backend node scripts/migrate-sqlite-postgres.mjs /data/qa-atlas.sqlite
docker compose up -d --build
```
Перенос выполняется транзакционно; исходная SQLite открывается readOnly, непустая целевая БД отклоняется. Не используйте SQLite backup/restore команды для PostgreSQL. Для новой БД используйте pg_dump/pg_restore средствами PostgreSQL. Сохраните старую копию до проверки результатов переноса. При новой установке миграция не нужна: docker compose up --build.

Локальные пароли/межсервисный токен по умолчанию предназначены только для localhost. Для сервера задайте POSTGRES_PASSWORD, ML_TOKEN и HTTPS PUBLIC_ORIGIN. PostgreSQL/Redis не публикуются на хосте.

## Реальные проверки и границы результата
Frontend/backend build прошёл перед последними конфигурационными изменениями; синтаксис адаптера и очереди проверен Node; regression таблицы «вход/ожидаемый результат» прошёл. Проверка Python импорта остановилась: в текущем runtime отсутствует httpx. Синтаксис Python проверяется отдельно. PostgreSQL, Redis, pgvector, миграция и Docker не запускались по просьбе пользователя. Реальный LLM не вызывался. Проверка файла 50+ страниц и нагрузочная проверка не выполнены. Нельзя считать соответствие всем критериям приёмки доказанным до запуска этого стека и проверки качества генерации. PG-адаптер совместимости использует worker и синхронное ожидание SQL: рассчитан на один backend и требует дальнейшего нагрузочного контроля.
