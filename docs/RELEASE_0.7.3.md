# QA Atlas 0.7.3 — точечные исправления

Проверена версия исходников 0.7.2 (приложенный ZIP). Изменения только в связанных с импортом, Gherkin, отображением и документацией модулях.

## Подтверждённые проблемы и изменения

- **BUG-001 / 002 / 014:** раньше `backend/src/jobs.mjs` делил результат импорта по 6000 символов и называл части «требованиями»; `ml-service/app/documents.py` отклонял текст >120000 символов. Теперь Python возвращает список отдельных найденных правил с оригинальным ID/страницей, backend сохраняет эти поля. Если атомарность не подтверждена, ставится маркировка для ручного выделения. Убрано ложное представление фрагментов как требований. В UI генератора есть поиск по ID, тексту и странице, выбор найденных и общий счётчик. Лимит 20 — только на контекст одного AI-запроса. Предел данных проекта и API синхронизирован до 8 МБ. Парсинг асинхронно запускается через существующую очередь.
- **BUG-008:** Gherkin-валидатор отклоняет типовые шаблонные Given/When/Then и Markdown в шагах, вместо сохранения бессмысленного теста. Реальный ответ внешней модели не проверялся.
- **BUG-003 / 004 / 005:** в 0.7.2 уже было управляемое поле количества и детерминированное соблюдение размера/уникальности набора; без необоснованного переписывания. Соответствующие JS-тесты в `tests/fixes071.test.mjs` сохранены.
- **BUG-006 / 007 / 009 / 010:** в 0.7.2 есть группировка рекомендаций, осторожные статусы ссылок, сохранение `duplicateOf` и проверка чисел в похожих сценариях. Не менялись без воспроизведения ошибок.
- **BUG-011 / 013:** в 0.7.2 Compose включает PostgreSQL, Redis, pgvector, ML и сборку worker-image; версия `decimal.js` зафиксирована на 10.6.0. Docker-сборка *не проверялась* в текущей среде. Для чистой установки требуется сетевой доступ к зависимостям.
- **BUG-012:** README обновлён под фактический стек и реальные API-маршруты 0.7.2+.
- **BUG-015:** конкретизированы счётчики выбора и статус требований, добавлен поиск.

## Реальные проверки

- Синтетический PDF на 51 страницу, более 120000 извлечённых символов: обнаружены `REQ-001` (стр. 1), `REQ-025` (стр. 25), `REQ-051` (стр. 51), без обрезания. Добавлена проверка HTTP `/parse` с этим PDF.
- Python unit: `python -m pytest -q tests/test_service.py tests/test_generation_validation.py tests/test_large_requirements.py` (см. фактические результаты в чате).
- Синтаксис JS и Python и TypeScript TSX разметка проверены инструментами в текущем окружении; полноценные Docker/LLM/browser E2E не запускались.

## Ограничения

- Автоматическое выделение атомарных бизнес-правил из документа без явных ID/структуры является эвристикой и требует ревью человеком. Если документ не структурирован, отображаются маркированные элементы для ручного выделения, а не фиктивные REQ.
- Сканы PDF без текстового слоя не читаются без OCR.
- Отсутствует доказательство успешного запуска Docker в **чистом** окружении; понадобится проверка на вашем компьютере и реальные учётные данные AI-провайдера.
- Уже импортированные старые `фрагмент N` в сохранённых проектах не преобразуются автоматически. Повторно импортируйте исходный PDF в новый проект или удалите устаревшие фрагменты после резервного копирования и проверки ссылок тестов.
- Анализ покрытия и генерация ограничены качеством требования и контекста; наличие связи с тестом не доказывает исполнение.
