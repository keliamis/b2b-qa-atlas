# QA Atlas 0.7.7 — P0: иерархия требований при импорте

## Исправлено

- В документах с явными `REQ-xxx` пункты `1.`, `2.`, `3.` и десятичные числа перестали создавать самостоятельные строки требований. Весь текст между соседними REQ сохраняется под родительским ID.
- В модели требования сохраняются `conditions` (дочерние условия), `page` и `pageEnd` (начальная и конечная страницы). Их не нужно считать отдельными требованиями при подсчёте покрытия.
- При повторяющемся заголовке одного REQ на границе страниц информация объединяется, повторный заголовок не создаёт ещё одну основную запись.
- DOCX извлекается в исходном порядке абзацев и таблиц.
- Повторный импорт с тем же именем файла пропускает существующие `originalId`; старые связи с тестами не удаляются и не переназначаются.
- На экране требований и в матрице показано число вложенных условий без отдельных строк матрицы.

## Проверка

- `python -m pytest -q ml-service/tests/test_requirement_hierarchy.py ml-service/tests/test_large_requirements.py ml-service/tests/test_service.py` при `PYTHONPATH=ml-service`: 16 passed.

- `node scripts/check-syntax.mjs`: 34 JS-модуля с корректным синтаксисом.
- Проверен синтаксис `backend/src/validation.ts`, `frontend/src/types.ts`, `frontend/src/App.tsx` через TypeScript transpiler.

## Ограничения

- Реальный файл пользователя `requirements_51_pages.pdf` не был приложен к этому запросу. Проверка выполнена на сохранённом синтетическом PDF с таким же количеством страниц и нумерованных условий.
- Уже импортированные 153 записи в существующем проекте **не удаляются автоматически**. Они могут иметь связи с тест-кейсами. Чтобы проверить исправленный импорт, загрузите документ в новый проект. Реконсиляция старых записей и тестов требует отдельной проверяемой операции.
- В этой среде отсутствуют установленный frontend/backend `node_modules` и Docker Engine, поэтому полная сборка и браузерный прогон не подтверждены; изменения минимальны и сохраняют формат существующего API.
- Документы без явных REQ обрабатываются осторожнее; неоднозначные блоки требуют ручной проверки. Нельзя гарантировать идеальное смысловое выделение произвольного документа без ревью.

## Установка

1. Сохраните `.env` и резервную копию Docker-томов PostgreSQL.
2. Распакуйте ZIP, перенесите `.env` в папку `qa-atlas`.
3. `docker compose up -d --build`
4. `docker compose ps` и `docker compose logs --tail=60 backend ml-service`
5. Загрузите исходный PDF в **новый** проект и сверьте ID / условия и матрицу прослеживаемости.

Не выполняйте `docker compose down -v`.
