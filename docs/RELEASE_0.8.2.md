# QA Atlas 0.8.2

- Удалены точки в двух строках крупного заголовка приветственного экрана.
- Исправлен контекст генерации тестовых данных: в UI выбирается правило, backend получает requirementId и передаёт только его полный текст.
- Выбор доступен для всех требований, включая REQ-051 и записи после сотой. Молчаливое slice(0,100) удалено.
- Проверка допустимых числовых границ теперь относится к выбранному правилу, а не к несвязанным требованиям проекта.
- Результат и JSON-экспорт содержат исходное требование. Переключение выбора и смена ревизии очищают старые данные.

Это генерация входных тестовых данных, а не импорт новых требований или генерация Gherkin. По умолчанию в выпадающем списке выбрано первое правило; при необходимости выберите другое перед запуском.

API POST /api/projects/:id/insights/data принимает {mode,count,requirementId}. Старый запрос без requirementId допускается только если в проекте ровно одно требование. При нескольких правилах возвращается понятное требование выбрать одно. Неизвестный ID отклоняется.

Текст выбранного правила не обрезается. Если одно отдельное требование само превышает 60 000 символов JSON-контекста, возвращается адресное сообщение с просьбой разделить это правило. Лимит провайдера не увеличивался; весь большой документ не подменяется сокращённой выдержкой.

Проверено: 9 целевых тестов, TypeScript, сборка frontend/backend — PASS. Проверен выбор REQ-051 в UI и выбор 151-го правила из большого проекта на backend. Живой LLM и Docker не проверялись. Пользовательские данные и миграции не изменены.

Обновление: сохраните существующую .env и выполните docker compose up -d --build. Не удаляйте volumes.
