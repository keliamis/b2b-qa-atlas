# QA Atlas 0.8.0: семантические эмбеддинги

## Что изменилось

Раньше слова распределялись по 128 позициям с помощью SHA-256. Это было лексическое сходство: разные слова с одинаковым смыслом могли оказаться далеко друг от друга.

Теперь embedding-модель превращает текст в массив чисел, обученный отражать смысл. «Вход в аккаунт» и «Авторизация пользователя» должны располагаться ближе друг к другу, чем «Добавление товара в корзину». pgvector хранит эти массивы и сравнивает их cosine distance. Он не создаёт эмбеддинги самостоятельно.

В интерфейсе появился поиск требований по смыслу. Он показывает ближайшие требования, не гарантирует их релевантность и не оценивает правильность тестов. Проверка качества на ваших реальных документах необходима отдельно.

## Yandex (при уже работающей генерации через Yandex)

Добавьте в существующую `.env`, не заменяя её полностью:

```dotenv
EMBEDDING_PROVIDER=yandex
YANDEX_FOLDER_ID=ваш_идентификатор_каталога
```

При AI_PROVIDER=yandex переиспользуется OPENAI_API_KEY. Если нужен отдельный ключ, задайте EMBEDDING_API_KEY. Ключ должен иметь права на вызов embeddings API. Наличие доступа к chat-модели не доказывает доступ к embedding-моделям.

По умолчанию реализация отправляет POST на `https://llm.api.cloud.yandex.net/foundationModels/v1/textEmbedding`, с авторизацией `Api-Key`, телом `{modelUri,text}`. Документы: `emb://<folder>/text-search-doc/latest`; запросы: `emb://<folder>/text-search-query/latest`. Это парные энкодеры одного векторного пространства. Нельзя смешивать произвольные doc/query модели. Размерность определяется ответом и проверяется, а не предполагается равной 128.

Не указывайте DeepSeek или gpt://... в EMBEDDING_MODEL: это модель генерации, не модель эмбеддингов. Не копируйте Chat Completions endpoint в EMBEDDING_BASE_URL.

Для нестандартных моделей можно явно задать EMBEDDING_MODEL и EMBEDDING_QUERY_MODEL. При изменении любых моделей/endpoint требуется перестроить индекс. Алиас latest может обновляться у провайдера без изменения URI; если доступна фиксированная версия, используйте её. После обновления модели провайдера перестройте индекс вручную.

## OpenAI-compatible API

Используйте провайдера, который действительно поддерживает `/embeddings`, а не только `/chat/completions`:

```dotenv
EMBEDDING_PROVIDER=openai
EMBEDDING_BASE_URL=https://api.openai.com/v1
EMBEDDING_MODEL=text-embedding-3-small
EMBEDDING_API_KEY=ваш_ключ
EMBEDDING_QUERY_MODEL=
EMBEDDING_DIMENSIONS=
```

Это пример конфигурации, не подтверждение доступности модели в вашем аккаунте. Документы и запросы используют одну EMBEDDING_MODEL. Переиспользование OPENAI_API_KEY допустимо автоматически только при совпадении AI_PROVIDER и EMBEDDING_PROVIDER; чтобы избежать неоднозначности, задайте отдельное поле EMBEDDING_API_KEY. EMBEDDING_DIMENSIONS необязателен: если задан, передаётся провайдеру и проверяется. Некоторые совместимые API не поддерживают этот параметр — оставьте пустым.

## Запуск и перестроение

```bash
docker compose up -d --build
# Проверяет реальные ответы embeddings API, не изменяет БД; расходует квоту:
docker compose exec backend node scripts/check_embeddings.mjs
```

Диагностика возвращает размерность и сходство запроса с двумя документами. smokePassed=true означает только удачный контрольный пример, не универсальную гарантию качества. Ошибки HTTP выводятся без тела ответа провайдера и без ключей. Если диагностика завершилась ошибкой, проверьте настройки и доступ к API.

В проекте откройте «Покрытие» → «Поиск требований по смыслу». Нажмите «Построить / обновить индекс». Дождитесь «Семантический индекс готов». Затем введите запрос другими словами. Построение проходит через существующую очередь задач, страницу можно закрыть. После изменения требований или моделей нажмите кнопку снова. Старые пользовательские данные и legacy-таблица хеш-векторов не удаляются; её содержимое больше не участвует в поиске.

Переиндексация полностью вычисляет новый набор перед транзакционной заменой. При ошибке API прежний индекс сохраняется. Если он относится к старым требованиям/модели, поиск не использует его. Одновременно допускается одна задача на проект; повторная отправка во время выполнения получает 409. При рестарте прерванное задание получает failed и требует повторного запуска. Отменить его можно в фоновых задачах.

Полный текст сохраняется: фрагменты до 1800 байт UTF-8, до 10000 фрагментов на проект. Yandex обрабатывается до 4 запросов параллельно, OpenAI — пакетами по 16 текстов. Один запрос ограничен 25 секундами, индексирование — 10 минутами. Автоматических повторов с неконтролируемым расходом квоты нет. На больших объёмах время, стоимость и качество необходимо измерить.

## REST API

Существующая сессия и права проекта обязательны. POST для поиска доступен viewer, перестроение — участнику с правом записи. Origin должен совпадать с PUBLIC_ORIGIN.

```bash
# Вместо PROJECT_ID используйте ID существующего проекта.
curl -b cookies.txt http://localhost:8080/api/projects/PROJECT_ID/insights/semantic-status
curl -b cookies.txt -X POST -H 'Origin: http://localhost:8080' -H 'Content-Type: application/json' \
  -d '{}' http://localhost:8080/api/projects/PROJECT_ID/semantic-index
# Возвращается 202 и ID фоновой задачи; следите за статусом:
curl -b cookies.txt http://localhost:8080/api/projects/PROJECT_ID/jobs
curl -b cookies.txt -H 'Origin: http://localhost:8080' -H 'Content-Type: application/json' \
  -d '{"query":"Авторизация пользователя"}' http://localhost:8080/api/projects/PROJECT_ID/insights/semantic-search
```
