# Обновление 0.5.2 → 0.6.0 через Docker Compose

Команды выполняются в каталоге проекта. Не заменяйте действующий `.env` примером, не меняйте имя Compose-проекта `qa-atlas`, не выполняйте `down -v`. Рабочие данные находятся в именованных volumes, они не входят в ZIP.

1. До замены файлов создайте резервную копию на старой версии. Используйте уникальное имя файла:

   ```sh
   docker compose exec backend node backend/src/backup.mjs /backups/before-0.6.0.sqlite
   docker compose cp backend:/backups/before-0.6.0.sqlite ./before-0.6.0.sqlite
   ```

   Сохраните копию вне каталога развёртывания вместе с действующим `.env` в закрытом месте. Проверьте, что команды завершились успешно.

2. Замените исходники содержимым обновлённого ZIP. Сохраните текущий `.env`, существующие volumes и локальные настройки прокси. Миграция БД добавляет таблицу токенов и поле подтверждения почты, не удаляет аккаунты или проекты.

3. При необходимости настройте почту в `.env`:

   ```dotenv
   SMTP_HOST=smtp.example.org
   SMTP_PORT=587
   SMTP_SECURE=false
   SMTP_USER=your-mailbox
   SMTP_PASSWORD=your-mail-provider-password
   SMTP_FROM=QA Atlas <qa@example.org>
   ```

   Для 587 используется обязательный STARTTLS; для 465 задайте `SMTP_SECURE=true`. Используйте действительный сертификат. `PUBLIC_ORIGIN` должен совпадать с адресом приложения: он используется в ссылках писем. Ключи AI-провайдера сохраняйте прежними. Без SMTP основной вход и регистрация работают, ссылки запроса писем скрыты. Подтверждение почты пока добровольное.

4. Соберите исполнитель и обновите сервисы:

   ```sh
   docker compose --profile build-worker build worker-image
   docker compose up -d --build --wait backend ml-service runner
   docker compose exec backend node scripts/check_runner.mjs
   docker compose ps
   ```

   Если используется HTTPS-профиль, поднимите его с прежними настройками:

   ```sh
   docker compose --profile https up -d --wait proxy
   ```

5. Проверьте вход существующего пользователя, новый аккаунт, создание проекта, загрузку требований и исходника, генерацию, прогон и экспорт. Затем архивируйте тестовый проект: редактирование должно быть запрещено; восстановите его через «Настройки». Проверьте сброс пароля и подтверждение почты через реальную почту, если SMTP подключён. Старые сессии после сброса должны перестать работать.

6. При сбое проверьте журнал, не публикуя секреты:

   ```sh
   docker compose logs --tail=100 backend ml-service runner
   ```

Для новой установки: `python3 scripts/init_env.py`, настройка `.env`, затем команды сборки из шага 4. Нужны Docker Engine/Desktop и доступ к реестрам образов и пакетам.

Откат: остановите backend, восстановите предыдущие исходники и резервную копию по `docs/OPERATIONS.md`. Не копируйте SQLite поверх работающей базы и не удаляйте WAL-файлы вручную. Резервная копия содержит приватные данные.

Эти команды подготовлены по конфигурации проекта, но не исполнялись в Docker в среде доработки.
