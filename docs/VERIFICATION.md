Дата: 30 октября 2026. Результаты получены при доработке приложенного проекта.

| Проверка | Результат |
|---|---|
| Установка зависимостей | `npm ci --ignore-scripts --no-audit --no-fund` успешно, затем добавлен nodemailer с фиксацией версии в lockfile; Python зависимости установлены из requirements.lock.txt |
| TypeScript | `npm run typecheck` — успешно |
| Сборка frontend/backend | `npm run build` — успешно: Vite production + esbuild backend |
| Синтаксис JS | `npm run check:syntax` — успешно, 23 модуля |
| Node unit/integration/UI | `npm test` — 40 passed, 0 failed |
| Python ML/runner | `PYTHONPATH=ml-service RUNNER_NODE_MODULES=<path>/node_modules python -m pytest ml-service/tests runner -q` — 32 passed |
| Production npm зависимости | `npm audit --omit=dev` — 0 известных уязвимостей на момент проверки; это не полный аудит безопасности |
| Compose | YAML разобран Python YAML-парсером; обязательные сервисы найдены. Это не `docker compose config` и не запуск |

Node-тесты включают реальный HTTP-сервер и SQLite: регистрацию, вход, CSRF, чужие проекты, ревизии, импорт, экспорт, backup, приглашения, viewer-права, дефекты, удаления, очередь и отмену. Проверка восстановления пароля использует настоящие хеши и БД с подменённой доставкой писем. jsdom-тесты проверяют форму регистрации, совпадение паролей, блокировку повторной отправки, управление тестами и отображение отчётов.

Python-тесты выполняют локальные pytest и Playwright Test для модулей, измеряют coverage.py/c8, проверяют падающие/пустые наборы, неимпортированные исходники, ошибки и таймаут. При итоговом запуске JS использованы @playwright/test 1.58.2 и c8 10.1.3, как в Worker.Dockerfile. Python runtime при локальной проверке: 3.12, pytest 9.2.0, coverage 7.17.0; версии образа остаются закреплены в Dockerfile (pytest 8.3.5, coverage 7.8.0). Полной эквивалентности окружению Docker не заявляем.

Контроллер Docker проверен с mock-клиентом, включая параметры изоляции. Тесты генератора используют моки AI, синтаксический анализ Python и настоящий `node --check` для JS. Они не подтверждают качество конкретной модели. Есть одно предупреждение DeprecationWarning от Starlette/AnyIO в тестовом окружении.

## Не выполнено

- Docker build/up/config, фактические контейнерные лимиты и healthchecks: Docker отсутствует.
- Настоящий браузер, E2E полного пользовательского пути, визуальные скриншоты, проверка всех ширин и WCAG: Chromium не скачался, локальный браузер отсутствует. jsdom не заменяет браузер.
- Реальные SMTP и AI-провайдер, документы >50 страниц, нагрузочные тесты и GitHub Actions.
- Полноценные ESLint/Ruff-проверки: конфигурация линтеров не введена. Выполнены парсинг, типизация, сборка и поведенческие тесты.

Воспроизведение: установите зависимости из package-lock.json и ML lockfile, инструменты runner из Worker.Dockerfile; затем выполните команды таблицы. Не запускайте недоверенные пользовательские тесты напрямую на хосте — локальные проверки здесь используют только контролируемые фикстуры проекта.
